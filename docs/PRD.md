# 自律庄园 PRD

## 1. 产品概述

「自律庄园」是一款游戏化身心管理产品。用户通过完成每日自律任务获得金币、经验和公益能量：金币用于建设自己的虚拟庄园，公益能量用于投入综合公益项目池。产品希望把“坚持自律”从抽象的意志力任务，转化为看得见、可积累、能反馈、也能连接社会价值的成长体验。

当前项目已有 Coze/Python Agent 原型，包含打卡、金币、等级、商店购买、自定义习惯等能力。本 PRD 面向作品集 Demo，对现有能力进行产品化整理，并规划一个可直接体验的 HTML 交互页面。

## 2. 背景与问题

很多年轻用户有健身、学习、阅读、早睡、日记等自律目标，但常常因为反馈太弱而中断。传统打卡工具通常只提供勾选、日历或连续天数，难以让用户感受到“我今天的努力改变了什么”。

本产品的核心判断是：自律行为需要更强的即时反馈和长期成长感。通过庄园建设、金币奖励和 AI 管家鼓励，可以让用户更直观地看到自己的投入，降低坚持成本。

## 3. 目标用户

- 想培养健康习惯的学生、求职者、初入职场人群。
- 有自我管理意识，但容易三天打鱼两天晒网。
- 喜欢轻量游戏化反馈，不希望使用复杂工具。
- 希望获得温和陪伴，而不是强压式监督。

## 4. 产品目标

### 用户目标

- 30 秒内完成一次打卡。
- 清楚看到今日完成进度。
- 获得金币、经验、公益能量和庄园变化反馈。
- 通过购买装饰形成长期动力。
- 将个人坚持投入动物救助、助学、灾区援助、环保、医疗援助等公益方向。

### 作品集目标

- 展示从用户痛点到产品机制的完整思考。
- 让面试官能直接体验核心闭环。
- 用一个小而完整的 MVP 体现产品落地能力。

## 5. 核心用户路径

1. 用户打开页面，看到今日任务和庄园状态。
2. 用户点击“健身”等习惯完成打卡。
3. 系统增加金币、经验和公益能量，更新今日进度。
4. AI 管家给出鼓励，并提示可以继续打卡、支持公益项目或查看商店。
5. 用户把公益能量投入综合公益项目池，看到对应项目进度增长。
6. 用户进入商店，用金币购买装饰。
7. 庄园展示新增装饰，用户形成成就感。
8. 数据闭环面板记录用户是否走完核心路径，用于后续复盘转化与留存假设。

## 6. 功能需求

### 6.1 今日打卡

内置六项习惯：健身、冥想、阅读、学习、早睡、日记。

规则：

- 每项每天只能完成一次。
- 成功打卡后金币 +10，经验 +10，公益能量 +10。
- 已完成任务显示完成状态，不重复奖励。
- 今日进度展示为“已完成数量 / 总数量”。

### 6.2 庄园状态

展示内容：

- 当前金币。
- 当前等级。
- 当前经验。
- 连续打卡天数。
- 今日完成进度。
- 已拥有装饰。

庄园视觉不追求复杂游戏画面，MVP 阶段采用轻量插画式布局，重点让用户感知“我的行为带来了变化”。

### 6.3 商店系统

商店展示物品名称、价格、是否已拥有、是否可购买。

购买规则：

- 金币足够且未拥有时，可以购买。
- 购买后扣除对应金币。
- 已购买物品出现在庄园中。
- 用户可以拖动已购买物品，决定其在庄园场景中的摆放位置。
- 用户可以点击庭院房门进入小屋，点击室内房门回到庭院。
- 用户可以消耗金币升级房子，房屋等级会改变外观与可装扮空间感。
- 金币不足时提示差额。

### 6.4 AI 管家反馈

AI 管家承担三类任务：

- 解释操作结果。
- 给出鼓励反馈。
- 提示下一步行动。

示例：

> 健身打卡成功，金币 +10。今天已经完成 2/6 项任务啦。小屋前的花圃又亮了一点，可以继续完成阅读，或者去商店看看有没有能买的装饰。

### 6.5 公益项目池

作品集 Demo 先采用“模拟公益闭环”，不接真实支付、不承诺真实捐赠。用户完成打卡后获得公益能量，并可将公益能量投入不同公益方向。

项目池包含：

- 动物救助。
- 困境助学。
- 灾区援助。
- 环保植树。
- 医疗援助。

规则：

- 每次投入固定消耗 10 点公益能量。
- 公益能量不足时按钮置灰，并由 AI 管家提示继续打卡。
- 每个公益项目展示目标、当前进度和影响说明。
- 真实落地阶段需要接入合规公益机构、品牌配捐、公开凭证和捐赠记录追踪。

### 6.6 作品说明区

页面下方加入作品集说明，内容包括：

- 项目背景。
- 用户痛点。
- 产品闭环。
- MVP 功能。
- 交互流程。
- 指标设计。
- 迭代方向。

### 6.7 新手引导与数据闭环

为了让面试官能在 30 秒内走完核心路径，Demo 增加 4 步新手引导：

- 完成一次打卡。
- 投入一次公益能量。
- 购买第一件装饰。
- 拖动摆放物品。

同时记录本地演示行为：

- 打卡次数。
- 公益投入次数。
- 商店购买次数。
- 摆放保存次数。
- 房屋升级次数。
- 核心路径完成率。

这些数据不代表真实上线用户数据，而是用于展示产品验证思路和未来埋点口径。

## 7. 非功能需求

- HTML Demo 应可直接打开使用，不依赖真实登录。
- 状态可存储在浏览器本地，便于演示。
- 页面需要适配桌面和手机。
- 交互按钮、状态卡片和商店项目不能因文字变化导致布局跳动。
- 文案风格温暖、清晰、产品化，避免过度幼稚。

## 8. 指标设计

如果后续真实上线，可关注：

- 新用户首日完成至少一次打卡的比例。
- 人均每日打卡项数。
- 次日留存率。
- 连续打卡 3 天、7 天用户比例。
- 商店购买转化率。
- 公益能量投入率。
- 公益项目偏好分布。
- 用户主动查看庄园次数。
- 核心路径完成率。
- 装饰摆放保存次数。
- 房屋升级触发次数。

作品集阶段可把这些指标作为产品思考展示，不需要真实采集。

## 9. MVP 取舍

本阶段保留：

- 打卡。
- 奖励。
- 庄园可视化。
- 公益项目池。
- 商店。
- AI 管家反馈。
- 作品说明。
- 新手引导。
- 数据闭环。

本阶段暂不做：

- 登录注册。
- 社交排行。
- 复杂任务模板。
- 真正的 3D 庄园。
- 真实支付、真实捐赠和公益机构结算。
- 医疗知识库问答。

理由：作品集第一版需要优先证明核心闭环是否成立，而不是扩展所有想法。

## 10. 后续迭代

1. 接入现有 Coze Agent 后端，使 AI 管家能理解自然语言操作。
2. 加入自定义习惯，让用户创建自己的长期目标。
3. 增加周报/月报，总结用户行为变化。
4. 增加庄园主题，如学习型、健康型、治愈型。
5. 接入合规公益机构或品牌配捐机制，展示公开凭证和项目进展。
6. 作为作品集第二阶段，扩展医疗知识问答 Agent，形成“轻量健康管理 + 专业知识问答”的组合项目。
